# LegalLens — Memory & Case Context

## 1. Purpose

LegalLens needs context so that analysis remains consistent across a user's case.

This file defines **application memory for a LegalLens case**.

It does not define ChatGPT's personal memory system.

The goal is to remember the information required to connect:

```text
User Situation
     ↓
Documents
     ↓
Evidence
     ↓
Conflicts
     ↓
Timeline
     ↓
Questions
     ↓
Preparation Brief
```

---

## 2. What LegalLens Should Remember

Memory should be scoped to the user's case.

### Case context

Store:

- case ID
- case title
- category
- user-described situation
- user-selected goals
- case status
- created/updated timestamps

Example:

```text
Category:
Employment

Situation:
"My company asked me to resign after 8 months..."

Goals:
- Understand obligations
- Find important dates
- Compare documents
- Find conflicting information
- Prepare questions
```

---

## 3. Document Memory

For every document, remember:

- document ID
- case ID
- filename
- document type
- page count
- processing status
- creation timestamp
- source/storage reference

Do not treat the filename alone as the document's identity.

---

## 4. Evidence Memory

Important extracted information should remain connected to its source.

Store:

```text
Evidence
 ├── document_id
 ├── clause_id
 ├── page
 ├── text
 └── evidence_type
```

A useful mental model is:

```text
Fact
 ↓
Evidence
 ↓
Document
 ↓
Page
 ↓
Section/Clause
 ↓
Source Text
```

This prevents later answers from losing their source.

---

## 5. Structured Fact Memory

The analysis layer may derive structured facts from documents.

Examples:

```text
Notice Period → 30 days → Offer Letter → Page 2 → Clause 5

Notice Period → 90 days → Employment Agreement → Page 7 → Clause 12
```

Facts should not exist without their evidence references when the source is available.

---

## 6. Conflict Memory

A conflict should retain:

- case
- topic
- description
- status
- supporting evidence

Example:

```text
Topic:
notice_period

Source A:
Offer Letter
30 days
Page 2
Clause 5

Source B:
Employment Agreement
90 days
Page 7
Clause 12

Status:
conflict
```

Memory should preserve the difference.

It must not transform the difference into an unsupported conclusion about which document legally controls.

---

## 7. Missing-Reference Memory

When a document refers to another document or policy, retain:

```text
referencing document
referenced item
source page/clause
found/not found
```

Example:

```text
Referenced:
Employee Handbook

Referenced by:
Employment Agreement

Status:
Not found in uploaded workspace
```

This should remain available to:

- Analysis
- Questions
- Q&A
- Brief

---

## 8. Timeline Memory

Store timeline events with:

```text
case_id
event_date
title
description
document_id
page
```

Example:

```text
12 Jan 2026
Offer Letter Issued
Source: Offer Letter, Page 1

20 Jan 2026
Employment Started
Source: Employment Agreement, Page 2
```

Never invent an event date.

If the source date is unclear, retain that uncertainty.

---

## 9. Question Memory

Questions belong to the case.

Store:

```text
id
case_id
question
category
status
```

Possible statuses include the workflow state needed by the UI, such as:

```text
open
discussed
```

Questions may be:

- generated by the system
- added by the user
- edited by the user
- deleted by the user

The user's edited version should be treated as the current question text.

---

## 10. Brief Memory

The preparation brief should be generated from existing case memory.

Inputs:

```text
Situation
+
Documents Reviewed
+
Key Evidence
+
Obligations
+
Important Dates
+
Areas to Review
+
Conflicts
+
Missing Information
+
Questions
+
Evidence Sources
```

Then:

```text
Brief Generator
      ↓
Evidence Validation
      ↓
Preparation Brief
```

The brief should not introduce facts that are absent from the stored case evidence.

---

## 11. Q&A Context Memory

When the user asks a question, retrieve relevant case context instead of sending the entire workspace.

Preferred context:

```text
Current Question
+
Relevant Situation
+
Relevant Document Chunks
+
Source Metadata
+
Relevant Conflicts
+
Relevant Timeline Events
```

Do not automatically include every document.

This keeps answers focused and reduces unnecessary exposure of sensitive content.

---

## 12. Evidence Status Memory

Every important statement can carry one of four statuses:

### FOUND DIRECTLY

Directly present in uploaded evidence.

### DERIVED FROM DOCUMENTS

Derived by combining multiple pieces of uploaded evidence.

### NOT FOUND

Not found in the uploaded workspace.

### NEEDS REVIEW

Conflicting or ambiguous evidence requires review.

These statuses should be available to the UI and answer-generation layer.

---

## 13. Memory Update Rules

### Rule 1 — Preserve source

When a new fact is extracted:

```text
Fact → Source metadata
```

must be stored together.

### Rule 2 — Do not overwrite conflicting facts

If two documents say different things, keep both.

Example:

```text
Notice Period
 ├── 30 days — Offer Letter
 └── 90 days — Employment Agreement
```

Create a conflict instead of replacing one value with the other.

### Rule 3 — Do not invent missing information

If a referenced document is unavailable:

```text
Status = NOT FOUND
```

Do not create a presumed value.

### Rule 4 — User edits have priority as user-provided context

If the user changes their situation description or question, retain the current user-provided version.

Do not silently rewrite the user's meaning.

### Rule 5 — Derived information remains derived

Do not turn an AI inference into a direct document fact.

---

## 14. Memory Lifecycle

```text
Case Created
    ↓
Situation Stored
    ↓
Documents Added
    ↓
Document Evidence Extracted
    ↓
Structured Facts Stored
    ↓
Conflicts / References / Timeline Stored
    ↓
Questions Stored
    ↓
Brief Generated
    ↓
User Updates Case
    ↓
Relevant Analysis Refreshed
```

When documents change, dependent analysis may need to be regenerated.

For example:

```text
Add Employee Handbook
        ↓
Re-run Reference Detection
        ↓
Missing Reference may change
        ↓
Questions/Brief may change
```

---

## 15. Memory vs. Source of Truth

Different data has different authority.

### User-provided case context

Source:

```text
User
```

Examples:

- situation description
- goals
- manually added questions

### Document facts

Source:

```text
Uploaded documents
```

Examples:

- clause text
- dates
- amounts
- obligations

### Derived analysis

Source:

```text
Application logic + evidence
```

Examples:

- conflict records
- timeline grouping
- derived explanations

### AI-generated text

Source:

```text
LLM using retrieved evidence
```

AI output must not become a source document.

## 17. Retrieval from Memory

For a question such as:

> What is my notice period?

The application should:

```text
Question
  ↓
Identify topic: notice period
  ↓
Retrieve relevant evidence
  ↓
Find Offer Letter evidence
  ↓
Find Employment Agreement evidence
  ↓
Detect conflict
  ↓
Generate neutral answer
  ↓
Attach sources
```

The answer should not rely on a generic legal-memory response when the user's documents contain the relevant evidence.

---

## 18. Memory for the Preparation Brief

The brief should be a derived view of the case, not an independent source of truth.

```text
Case Data
+
Evidence
+
Analysis
+
Questions
        ↓
Preparation Brief
```

If source evidence changes, the brief can be regenerated.

---

## 19. Privacy Rules for Memory

Because legal documents can be sensitive:

- keep memory scoped to the correct user/case
- do not expose one user's case memory to another user
- do not log complete memory contents unnecessarily
- do not send unrelated case information to the LLM
- do not store secrets inside case memory
- preserve only information required for the product workflow

See `security.md` for detailed controls.

---

## 20. What Memory Must Not Do

LegalLens memory must not:

- decide legal outcomes
- decide which document legally controls
- create missing facts
- turn an AI guess into evidence
- infer a user's legal rights without supporting documents
- predict court outcomes
- produce a legal-risk score
- replace professional legal review

---

## 21. Memory Definition of Done

Memory is implemented correctly when:

- case context persists
- documents remain connected to their case
- extracted facts retain source metadata
- conflicting facts are preserved rather than overwritten
- missing references remain visible
- timeline events retain sources
- questions persist and can be edited
- Q&A retrieves relevant case evidence
- briefs can be regenerated from current case data
- cross-user data access is prevented

---

## 22. Core Principle

> **Remember the evidence and the user's case context; never remember unsupported conclusions as facts.**
